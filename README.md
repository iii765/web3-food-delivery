# 🛵 Web3 去中心化外卖平台

> 创建日期：2026-07-15
> 状态：📝 方案阶段
> 核心洞察：美团抽佣25%养肥了平台，商家/骑手/用户三方都在输。区块链能让中间人变得几乎免费。

---

## 一、行业痛点

| 角色 | 痛点 | 量化 |
|------|------|------|
| 商家 | 美团/饿了么抽佣18-25% | 30元客单价，到手<24元，扣除成本后净利润接近0 |
| 骑手 | 算法调度压榨，配送费被抽30-40%，无社保 | 每单实际收入远低于平台显示 |
| 用户 | 平台费转嫁→价格上涨，商家被迫降质 | 花更多的钱吃更差的饭 |
| 平台 | 两头通吃 | 美团2024年净利润~350亿 |

**本质问题：** 外卖平台的信任中介价值已远低于它抽取的租金。当撮合成本接近零时，平台就只剩下垄断租金——这正是被颠覆的窗口。

---

## 二、解决方案

### 核心思路
用**智能合约**替代平台作为"可信第三方"：
- 撮合 → 用算法+社区（非专利）
- 托管 → 用合约（非平台账户）
- 分账 → 用合约自动执行（非人工结算）
- 信誉 → 用链上记录（非平台黑箱）

### 价值主张
| 角色 | 传统平台 | Web3平台 | 改善 |
|------|---------|---------|------|
| 商家 | 到手75% | 到手85% | +13%利润 |
| 骑手 | 到手60-70% | 到手12%分账 | 透明+信誉资产 |
| 用户 | 平台溢价 | 更便宜10-15% | 品质更好 |
| 协议 | — | 抽取3% | 用于生态循环 |

## 三、技术架构

### 3.1 智能合约层（链上）

```
OrderContract.sol          — 订单生命周期
  ├─ createOrder()         — 用户下单，资金托管
  ├─ acceptOrder()         — 商家接单
  ├─ assignRider()         — 分配骑手
  ├─ confirmDelivery()     — 用户确认收货
  ├─ dispute()             — 争议仲裁
  └─ autoSettlement()     — 自动分账

ReputationContract.sol    — 链上信誉
  ├─ rateMerchant()
  ├─ rateRider()
  ├─ rateUser()
  └─ getScore()           — 公开可查

TokenContract.sol         — 双代币模型
  ├─ $FOOD (ERC-20 治理)  — DAO投票 + 质押收益
  └─ $BITE (ERC-20 积分)  — 消费奖励 + 骑手补贴

DAOVault.sol              — 协议金库
  ├─ collectFees()        — 3%协议费归集
  ├─ propose()            — 社区提案
  └─ vote()               — 链上投票
```

### 3.2 链下服务层

```
智能合约 ←→ Subgraph (The Graph 索引)
                 ↓
          API Gateway (订单查询/用户数据)
                 ↓
     ┌───────────┼───────────┐
  商家端App   用户端App   骑手端App
  (接单/对账)  (下单/支付)  (接单/导航)
```

### 3.3 支付抽象层（关键）

**用户不需要知道自己在用区块链：**
- 前端：微信/支付宝
- 后端：法币→USDC→智能合约
- 入金走 OTC/Payment Provider（如 Alchemy Pay、Ramp）
- Gas 费由协议金库代付（meta-transaction）

### 3.4 推荐技术栈

| 层级 | 选型 | 理由 |
|------|------|------|
| 公链 | Monad / Arbitrum | 高TPS、低Gas、EVM兼容 |
| 合约 | Solidity + Hardhat | 已熟悉 |
| 索引 | The Graph | 链上数据查询 |
| 存储 | IPFS + Arweave | 商家菜单/图片存证 |
| 前端 | React Native / 微信小程序 | 双端覆盖 |
| 后端 | Node.js + PostgreSQL | 链下业务逻辑 |
| 支付 | Alchemy Pay / MoonPay | 法币入金 |

## 四、代币经济学

### 4.1 双代币模型

**$FOOD — 治理代币（有限供应）**
- 总供应量：1亿枚
- 分配：
  - 40% 社区激励（流动性挖矿 + 骑手奖励）
  - 20% 团队（4年线性解锁）
  - 15% 生态基金（DAO金库管理）
  - 15% 早期投资者
  - 10% 空投（早期商家/用户）
- 用途：DAO治理投票、质押收益（协议费分红）、Gas补贴
- 价值捕获：协议收入→回购$FOOD→分配质押者

**$BITE — 积分代币（无限增发，中心化控制）**
- 用途：消费返利、新用户奖励、骑手补贴、兑换优惠券
- 锚定：1 $BITE ≈ 0.01 USDC（协议可控汇率）
- 燃烧：兑换优惠券后销毁

### 4.2 经济飞轮

```
用户消费 → 获得$BITE → 兑换优惠券 → 再次消费
   ↓
协议收入(3%) → 回购$FOOD → 质押者分红
   ↓
商家利润↑ → 品质↑ → 用户↑ → 骑手↑ → 网络效应
```

## 五、冷启动策略

### 5.1 阶段一：大学城MVP（0-3个月）

**目标：** 1所大学 + 10家商家 + 100个活跃用户

**范围：** 就做一所大学城周边（比如你的学校）
- 商家画像：夫妻店/小档口，被美团抽佣最痛的
- 用户画像：学生，价格敏感，愿意尝鲜
- 配送：自配送商家优先（校内/步行可达），暂不建骑手网络

**激励：**
- 商家：前3个月免协议费，入驻送$FOOD
- 用户：首单5折（协议补贴），每单返$BITE
- 推荐：用户推荐商家入驻得$BITE

### 5.2 阶段二：区域扩张（3-12个月）

- 覆盖3-5所大学城
- 引入骑手端App
- 上线DAO治理（商家/用户参与投票）
- 接入稳定币支付（USDC）

### 5.3 阶段三：城市级运营（12个月+）

- 覆盖一个二线城市
- 引入动态定价算法
- 探索广告/竞价排名等增值收入
- 完全DAO化治理

## 六、风险 & 应对

### 🔴 致命风险

| 风险 | 严重度 | 应对 |
|------|--------|------|
| **冷启动鸡生蛋** | 🔴🔴🔴 | 聚焦极小区（1个大学城），不追求规模。先让10家店活得好，再谈扩张 |
| **用户不装钱包** | 🔴🔴🔴 | 支付抽象层，用户无感区块链。微信下单→后台合约结算 |
| **配送履约** | 🔴🔴 | 阶段一用自配送商家，不碰骑手调度。优先级：先跑通交易分账，再管物流 |
| **食品安全监管** | 🔴🔴 | 商家需提供实体经营资质上链存证，协议不为黑商户服务 |
| **争议仲裁** | 🔴🔴 | 多签仲裁委员会（社区选举），链下证据链上裁决。逐步过渡到去中心化仲裁协议（Kleros） |

### 🟡 中等风险

| 风险 | 应对 |
|------|------|
| 骑手供给不足 | 阶段一绕过，阶段二用$BITE补贴 + 弹性定价吸引骑手 |
| 代币价格波动 | $BITE锚定协议控制汇率，$FOOD长期价值靠回购支撑 |
| 竞争巨头进入 | 差异化：非平台化 + 社区所有。巨头难以放弃25%抽佣模式 |
| 法币出入金合规 | 用持牌支付商（Alchemy Pay），不自己碰资金池 |
